# Packaged Codex plugin process E2E

The `e2e` command in `ci.json` runs `node scripts/ci-e2e.mjs`.
The test copies the self-contained `codex/` package into a temporary directory whose name contains a space. It resolves hooks and skills from the copied `.codex-plugin/plugin.json` and invokes the shipped commands as real child processes with isolated `PLUGIN_ROOT` and `PLUGIN_DATA`.

The sequence starts a session, submits a prompt, requests a permitted file edit, performs that edit, and reports its result through PostToolUse. It then requests an edit to a canonical wiki page and requires the guard to deny it while preserving the page. Telemetry must contain the ordered events and outcomes without retaining the prompt or file/tool contents. Finally the packaged autopilot skill must return its documented critical-task guidance with enforcement disabled. No runtime module is mocked or imported directly by the test.

This is evidence for package relocation and command-process integration. It does not launch Codex, install or trust hooks in the native host, select a model, or prove Claude plugin compatibility. Those boundaries retain their existing verification steps. The test invokes no paid model and cleans its temporary package, files and telemetry on completion or failure.

Local validation on macOS with Node v26.11.1: the exact `ci.json` E2E command passed, all 28 existing `codex/tests/*.test.mjs` tests passed, and `sh scripts/check-shared.sh` passed. `node --check scripts/ci-e2e.mjs` and `git diff --check` passed. The CI Node 24 runtime was not available locally; its execution remains a hosted-CI check.
